# Импорт проектов и тредов из Claude Code, Codex и Antigravity: план

Статус: v6, после трёх раундов ревью Codex и Gemini (§9). Решения §8 приняты владельцем 2026-11-26; реализация идёт на ветке `cli-import`.
Макеты: `docs/design/cli-import/mockups/import.html` (варианты A, B, C и экран после импорта, светлая и тёмная тема).

## 1. Задача

Владелец, 2026-11-26: «я бы хотел иметь возможность импортировать проекты и треды из claude / codex / antigravity». Тред, начатый в CLI (терминал, Claude desktop, Codex Desktop, расширение VS Code, agy), должен стать чатом AccordAgents в своей папке и продолжаться в нём.

## 3. Можно ли сделать честно

Да, для Claude Code и Codex полностью, для agy с оговоркой про папку, для приложения Antigravity нет.

Механизм. Импортированный тред становится обычным чатом в режиме Sessions: в папке треда, с одним участником, главной сессией, у которой провайдер, модель и id сессии взяты из треда. Сообщения пользователя идут в ту же сессию CLI его собственным resume, тем же кодом, которым главная сессия продолжает свою сессию со второго хода: `claude --resume <id>`, Codex `thread/resume`, `agy --conversation <id>`. История для показа копируется один раз при импорте из транскрипта в сообщения чата.

Сессия CLI при этом не знает, что она теперь главная сессия чата. Claude Code держит системный промпт, записанный при первом запросе, до сжатия контекста (`claude/launch.ts:119-130`), поэтому `--append-system-prompt` в импортированную сессию не попадёт. Значит первый ход импортированной сессии отправляется как первый ход новой сессии, а не как продолжение (§6.3): полные инструкции чата, инструкции роли главной сессии, индекс памяти и одна строка о том, откуда сессия. Эти инструкции остаются в исходной сессии CLI: если вернуться к ней в терминале, она будет помнить, что работала в AccordAgents.

Проверка по `docs/parity-requirements.md`:

- **Требование 2 (как в CLI).** В каждом CLI выбор треда в resume продолжает эту самую сессию, и импорт делает то же. Список такой, как в приложении вендора («Список Claude», «Список Codex», «Список Antigravity» в §4): у Claude боковая панель приложения Claude, у Codex треды его `thread/list` по проектам приложения Codex, у agy переписки, которые показывает приложение Antigravity. Форк вместо продолжения сделать для всех нельзя: у agy форка нет (поэтому и Fork to new chat недоступен для Antigravity). Где CLI позволяет продолжить, приложение тоже позволяет, с теми же последствиями.
- **Требование 1 (локальный = облачный).** Импортированная главная сессия ведёт себя как любая локальная главная сессия, включая перенос: Claude Code переезжает на машину со своей сессией (`memberSessionMoves`), а Codex и agy, как любой участник, который уже работал, остаются там, где начали (`chatMembers.ts:141-160`). Список тредов в v1 читается только с этого компьютера: треды, которые пользователь запускал в CLI прямо на облачной машине, не видны. Это расхождение с требованием 1, нужно решение владельца (§8.6).
- **Worktree.** Приложение ничего не создаёт и не удаляет. Тред, сделанный в worktree-папке (у Claude 12, у Codex 5), импортируется в эту папку как есть.
- **Ничего в обход сервера.** Импорт читает файлы CLI на этом компьютере, чат сохраняется локально и уходит на сервер через его очередь записями `chat.import`, которые сервер уже принимает от компьютера (§6.3). Новых путей между устройствами нет. Телефон видит импортированные чаты как любые; сам импорт есть только на компьютере, потому что данные CLI лежат там.

Расхождения, которые требуют решения владельца (§8) и, если он их примет, записи в реестр `docs/parity-requirements.md`:

1. История показывает только текст вопросов и ответов: без шагов инструментов и без картинок (на месте картинки строка «Image»). В CLI после resume видна вся история. Близко к открытому дефекту «Old tool steps lose their details»; полную историю шагов можно добавить позже тем же решением (читать шаг из лога CLI при раскрытии).
2. Ходы, сделанные в CLI после импорта, в ленте чата не появляются, а тёплый процесс узнаёт о них только после перезапуска (§4).
3. Список тредов только с этого компьютера (выше).

## 4. Крайние случаи

- **Папка удалена.** Чат не может запустить CLI в несуществующей папке (агент запускается с `cwd` = папка чата, `geminiRuns.ts:379`, `roleRuntime.ts:159`). Поэтому для треда с удалённой папкой пользователь при импорте выбирает существующую папку (Choose folder), исходная сохраняется в отметке происхождения. Claude и Codex продолжают сессию в новой папке (проверено). agy продолжает переписку, но его инструменты остаются в старой папке (проверено): строка говорит «Antigravity keeps this thread's old folder: its commands will fail», импорт не запрещён, как не запрещает его сам agy.
- **Перенос на машину и обратно.** Возврат сессии Claude с машины заменяет транскрипт на Mac (`memberSessionFiles.ts:75`): если пока участник был на машине, тот же тред продолжали в CLI на Mac, эти ходы пропадут. Так сейчас работает перенос любого участника Claude; в v1 не меняется, записано как известное ограничение.
- **Дубли.** Тред уже в приложении, если его id (у Codex `Thread.id`, не `Thread.sessionId`, который общий на дерево тредов) есть у сессии любого участника любого чата или в отметке происхождения любого импортированного чата (читается без сообщений, только поля чатов, `conversationReads.ts`) (id сессии может смениться после хода, `pendingReplies.ts:232-240`, и запись сессии уходит при переносе, `chatMembers.ts:203`). Такой тред не выбирается и показывает «In AccordAgents, Open». У Codex так отсеиваются и 11 тредов, созданных приложением. Повторный импорт никогда не делает второй чат.
- **Resume не удался.** Сегодня главная сессия, чья сессия CLI пропала, молча начинает новую сессию из контекста чата и показывает предупреждение (`claudeRuns.ts:414`, `geminiRuns.ts:437`). Для импорта это значило бы, что Continue не продолжил тред. Поэтому в список попадают только источники, чьё продолжение проверено (§7.1); тред из непроверенного источника показан со статусом и причиной и не выбирается. Пока первый ход импортированной сессии не прошёл (`importIntroPending`), пропавшая сессия (resume не нашёл её или перенос на машину пришёл без транскрипта, `memberMoves.ts:154`) даёт ошибку «Could not continue the Claude Code session: …», а не новый старт: запасной промпт берёт только сообщения после указателя (`promptContext.ts:72,83-85`), то есть новая сессия не получила бы импортированной истории, а предупреждение `pendingReplies.ts:244` при этом говорило бы обратное. Чат и id остаются. После первого успешного хода работает существующее поведение, как у любого участника.
- **Тред недавно менялся в CLI.** Свежее изменение не доказывает, что CLI открыт. Строка показывает «Updated 2 min ago» с предупреждением, что продолжение в двух местах перемешает ходы; выбрать её можно.
- **Ходы в CLI после импорта.** В v1 приложение их не отслеживает: ни дописывания ленты, ни предупреждения. После первого хода в транскрипте лежат и ходы самого приложения, так что «всё после импорта» задвоило бы их, а честное различение требует курсора, который двигают ходы приложения, Restart и перенос сессии, это отдельная работа. Тёплый процесс Claude или Codex держит сессию загруженной (`appServerThread.ts:129`) и не видит ходов, сделанных в CLI, до перезапуска (существующий Restart или перезапуск приложения), ровно как второй процесс CLI на той же сессии; agy запускается заново на каждый ход и читает сессию с диска. Проверка в §7.4. Это расхождение 2.
- **Большие транскрипты.** Файлы до 270 МБ, но текста в них 0.8%: файлы читаются потоком построчно; Codex читается своим API страницами. Самый большой тред: 1831 сообщение и 773 тыс. символов; самое большое сообщение 343 тыс. символов (на сервере предел одной записи 4 МБ, `HUB_OP_MAX_BYTES`). Чат собирается целиком и сохраняется один раз (§6.3). Без отметки «уже прочитано» вся история ушла бы в первый ход как контекст чата (`promptContext.ts:66-78`), а agy получает промпт в argv (`geminiExec.ts:98`) и упал бы с E2BIG: указатель контекста главной сессии ставится на последнее импортированное сообщение.
- **Список Claude.** **Решено владельцем 2026-11-26: в списке только треды, которые показывает приложение самого вендора.** У Claude это записи сессий приложения Claude desktop, `<appData>/Claude/claude-code-sessions/<аккаунт>/<организация>/local_<uuid>.json`, всех аккаунтов: по треду на каждую неархивную запись, чей транскрипт (`cliSessionId`) есть на диске. Заголовок из записи, как в боковой панели; папка из транскрипта; время из `lastActivityAt`. Сессия в worktree показывается под репозиторием, к которому её относит приложение (`originCwd`), побочная сессия под той, из которой её запустили (`spawnedFrom`). Сессии терминала, eval-прогоны и сабсессии без записи приложения в список не попадают: на этом Mac 157 тредов из 163 записей вместо 808 сессий (у 6 записей нет транскрипта). Нет папки приложения Claude: Claude показан недоступным с причиной, как CLI без своих данных.
- **Список Codex.** То же решение владельца. Приложение Codex (ChatGPT.app, Codex 0.170, данные в `CODEX_HOME`) берёт треды тем же `thread/list` app-server без фильтра источников (`exec` и сабагенты не входят, архивные тоже) и показывает их по проектам. Проекты и их корни читаются из `project/list` того же app-server (23 здесь; в `state_<n>.sqlite` те же таблицы `projects` и `project_roots`, но в базы Codex импорт не ходит). Боковая панель приложения в `CODEX_HOME/.codex-global-state.json`: `thread-project-assignments` (тред, который пользователь положил в проект; часть по id проекта до переезда проектов в app-server, они сводятся через `app-server-project-id-by-legacy-project-id-by-host` и `local-projects`), `projectless-thread-ids` (чаты вне проектов, `~/Documents/Codex/<дата>/…`), `pinned-thread-ids`. Тред в списке, если он назначен в проект, или это чат вне проектов, или его папка внутри корня проекта (самого глубокого), или он закреплён. `project` у треда: корень его проекта, когда это не сама папка треда (Codex-worktree `~/.codex/worktrees/<id>/<repo>`, подпапка). Треды с `originator` `accordagents` создал сам AccordAgents через app-server, их нет никогда. Заголовок: `name`, иначе `preview` из `thread/list`. На этом Mac 26.11.2026: 944 треда в `thread/list`, в списке 796 (551 по корню проекта, 201 назначен, из них 5 вне всех корней, 48 чатов вне проектов), 23 свои, 125 вне всех проектов не показываются. Нет `.codex-global-state.json`: Codex недоступен с причиной «The Codex app keeps no threads on this computer», app-server при этом не запускается. Список читается 10.7 с, почти всё это `thread/list`.
- **Список Antigravity.** То же решение владельца. Менеджер агентов приложения Antigravity показывает переписки из `~/.gemini/antigravity/conversation_summaries.db` (те же id в `agyhub_summaries_proto.pb`): здесь 146, из них 102 созданы в приложении и 44 в agy (`source` `CORTEX_TRAJECTORY_SOURCE_CLI`). Переписку приложения `agy --conversation` не продолжает («trajectory not found»), поэтому в списке только переписки agy (`~/.gemini/antigravity-cli`, его сводки), которые есть и в базе приложения, и чей файл переписки на месте: 44 из 211 строк agy. Папка и время из сводки agy, заголовок из сводки приложения, если он там есть (у 2 из 146 строк, у переписок agy ни у одной), иначе превью agy. Переписка agy, которую приложение ещё не видело (оно не запускалось после неё), в список не попадает, пока приложение её не покажет. Нет базы приложения: Antigravity недоступен с причиной «The Antigravity app keeps no conversations on this computer».
- **Автоматические прогоны.** Отдельного переключателя нет: в списке только то, что показывают приложения вендоров. У Claude SDK-сессий нет в записях приложения Claude, у Codex `exec` и сабагентов нет в его `thread/list` без фильтра источников, у agy разовые прогоны `--print` не попадают в список приложения Antigravity, пока оно их не покажет. Временная папка автоматическим прогоном не считается: такие треды попадают в группу «Folder is gone», которая свёрнута по умолчанию.
- **Модель, effort, режим.** Модель и effort из треда (Claude: модель последнего ответа; Codex: `model` и `reasoningEffort` из `Thread` app-server; agy: модель из транскрипта). Режим доступа: тот, что выберет первый шаг реализации, повторив поведение resume каждого CLI (§7.2). Сегодня приложение на resume всегда передаёт свой режим и песочницу (`claude/launch.ts:64-65`, `appServerParams.ts:70-72`), а agy не передаёт `--model` (`geminiExec.ts:109`).
- **Заголовок.** Claude: заголовок из записи приложения Claude, как в его боковой панели; без него свой заголовок сессии, иначе первая строка первого сообщения, как в списке resume. Codex: `name`, иначе `preview` из `Thread` app-server. agy: заголовок из сводки приложения Antigravity, иначе превью. Автопереименование приложения не сработает (в чате уже есть сообщения, `titles.ts:66`), и не нужно: заголовок CLI остаётся, переименовать можно руками.
- **Папки данных CLI** берутся из окружения участников (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `memberSessionFiles.ts:31-35`), а не из жёстких путей в домашней папке.

## 5. UI/UX

Макет: `docs/design/cli-import/mockups/import.html`.

- **A. Диалог «Import threads».** Открывается кнопкой у заголовка Projects в сайдбаре и ссылкой из New chat. Сверху вкладки All / Claude / Codex / Antigravity с числами и поиск. Слева проекты, как их называет приложение, сначала существующие по свежести, затем «Folder is gone»; строка проекта в одну линию: галочка (все его треды), имя, число; полный путь только в подсказке и в шапке справа. Справа треды выбранного проекта: глиф CLI, заголовок, состояние, время; дочерние сессии Claude с отступом под родителем; импортированный тред: «Imported» и кнопка Open. Внизу «N selected», предупреждение о недавно менявшемся треде и кнопка Import. Для удалённой папки над её тредами Choose folder (полировка по замечаниям владельца 2026-11-26).
- **B. Блок в New chat.** Под заголовком New chat всегда есть маленькая ссылка «Browse CLI threads» (открывает A для этой папки), она не зависит от того, прочитан ли список. 2. **Чтение** (`src/main/services/cliImport.ts` и папка частей), по читателю на CLI. Claude: список из записей сессий приложения Claude (`cliImport/claudeAppSessions.ts`, папка `appData` от Electron), транскрипты находятся одним проходом по папке `projects`; потоковое чтение jsonl, переиспользуя разбор строк из `forkCut.ts` и поиск файлов из `memberSessionFiles.ts`. Codex: отдельный короткоживущий `codex app-server` (`thread/list`, `project/list`, `thread/turns/list`, `thread/items/list`), как каталог моделей в `modelCatalogs.ts`; общего подключения к app-server нет; проекты приложения Codex по правилам «Списка Codex» (`cliImport/codexAppProjects.ts`). agy: `conversation_summaries.db` agy и приложения Antigravity через `sqlite3` только на чтение и `transcript_full.jsonl`.
3. **Создание чата** по образцу `ChatForks.createForkedConversation`:
   - главная сессия с провайдером, моделью и effort треда; на участнике неизменяемая отметка `importOrigin` (провайдер, id сессии, исходная папка, когда), которую пишет только компьютер: сервер снимает её с участника, которого добавляет машина (`withoutComputerOnlyFields`, `hubMachineScope/memberFields.ts:16-21`, там же `forkOrigin`), и сохраняет при обновлениях от машины (`HOME_FIELDS` и `keepHome`, `memberFields.ts:23-31`);
   - запись сессии создаётся обычным путём (`MemberSessions.newSessionForParticipant`) с id треда и признаком `importIntroPending`;
   - первый ход: полные инструкции чата (`turnPrompt.ts:110-115`, они уже содержат инструкции роли, второй раз их не слать), индекс памяти и строка об импорте (запасного промпта для неудачного resume на первом ходу нет: пока стоит `importIntroPending`, такой resume даёт ошибку, §4); `importIntroPending` снимается только после успешного хода (`participantTurn.ts:802-808`) и переезжает вместе с сессией Claude при переносе на машину до первого хода (поля сессии копируются списком, `memberMoves.ts:513-529`; `instructionsAccessHash` в нём нет, поэтому опираться на него нельзя);
   - история: сообщения пользователя без `deliveryTargets` (иначе сервер запросит по ним настоящие ходы, `hubOps/chatRecords.ts:137`), ответы от имени главной сессии; у каждого законченного ответа Claude и Codex отметка хода CLI `sessionCut` (uuid сообщения у Claude, id хода у Codex), иначе Fork to new chat сразу после импорта не найдёт, где резать копию, и скопирует всю сессию вместе с ходами, сделанными в CLI позже (`forkToNewChat.ts:184-187,215-216`); `promptContextPointers` главной сессии на последнем импортированном сообщении;
   - чат собирается целиком и сохраняется локально один раз (сохранение берёт весь снимок, `storage/conversations/conversationSaves.ts:149-189`), и в той же транзакции в очередь на сервер (`hub_client_ops`) кладутся страницы `chat.import` (их сейчас шлёт только разовый переезд чатов, `serverChatLink.ts:877-915`; сервер принимает их от компьютера, `hubOps/imports.ts`). Обычное сохранение нового чата дало бы `conversation.create` и по `message.create` на сообщение (`chatStore.ts:400-420`): 1832 записи, и на каждое законченное сообщение ответа сервер звонит на телефон (`src/hub/main.ts:183-194`), то есть сотни уведомлений за один импорт, плюс 1832 сохранения чата на сервере. `chat.import` уведомлений не шлёт и уходит примерно десятком записей;
   - что учесть: resync сохраняет неотправленный чат только по `conversation.create` в очереди (`serverChatLink.ts:665`), надо учитывать и `chat.import`; `applyServerEntriesFor` (`serverChat.ts:127`) обрабатывает `chat.import` явно: промежуточные страницы пропускает (сейчас свои страницы проходят дальше и каждая пересохраняет весь чат, а чужие перечитывают его), на последней перечитывает чат один раз (в пачке ленты с обычными изменениями пропускаются только записи `chat.import`); при первой привязке к серверу (`chatStore.ts:476-481`) неотправленные `chat.import` этого чата снимаются вместе с остальными его записями (`settleMoved`, `hubOpsClient.ts:542` сейчас снимает только `conversation.*` и `message.*`), иначе их повтор вернул бы старый заголовок (`imports.ts:44`); место импортированных сообщений в порядке сервера (`imports.ts:65,86`, `chatServerOps.ts:154-166`) берётся из ответа сервера, а не ставится заранее: ранний `serverSeq` потерял бы неотправленные страницы при resync (`serverChatLink.ts:659`);
4. **Видимая строка импорта**: новый вид сообщения, который не скрывается как системный, на компьютере (`chatTimelineVisibility.ts`), на сервере (страницы телефона собирает он, `hubPhone.ts:384`) и в PWA; значит, в работе обновление сервера и деплой PWA (`docs/deploying-the-phone-app.md`).
